# 0003 · 对齐基线：容差、金标准口径、以及第二次参考运行的授权

**背景**：A 侧第 2 轮完成了**三级对齐**，全部通过（见 `docs/status-deepseek.md`）：
权重 **428/428 张量逐字节一致**（比对载荷 765,013,216 B，差异 0）；
tokenizer 往返 **2.4e-07**（latent 是 1/32 离网格 ⇒ 量化层级逐个命中）；
denoiser **10 步全部**逐条断言，三路原始 **2.76e-05**、CFG 合成 **5.39e-05**、DDIM 更新 **1.23e-05**；
整段 40 帧 `frames (T,330)` **1.869e-05**（root/heading 对参考 npz **5.1e-06 / 3.0e-06**）。

## 裁定

1. **容差 1e-3 冻结**为对齐判据（信号 O(1)，实测残差 1e-7~5.4e-05；结构性错误是 O(1e-1)）。
   **可证伪性已在案**：负对照 `x_T += 0.25` → max_abs **2.56**，是容差的 **2560×**。任何新比较都必须附这种负对照。
2. **金标准口径冻结**：两侧都 `--no-postprocess`（沿用 `0002` 裁定 2）；金标准保留 foot skating，
   与 Core 官方默认产物有系统性差异，**报告须写明**；B 侧不必移植 `MotionCorrection` C++ 扩展。
3. **对齐不依赖复刻 CUDA RNG**：金标准 dump 了参考自己的 `x_T`，我们注入同一噪声起步（seed 语义对齐是独立课题）。
4. **授权第二次参考运行**（用户已说"直接搞完、不要等我"）：参数 `--duration 4.0`（= 2 个自回归窗口）、
   其余同上（同 prompt、`--seed 0`、`--no-postprocess`、文本编码器放 CPU bf16）。
   目的：给**多窗口路径**（history cropping、多次 recenter、`first_heading_angle` 更新）补金标准——
   目前只有单窗口这一支被验证过，**多窗口是未验证的**。
   纪律同前：一次且仅一次、跑完立即停进程、报告峰值显存/内存/耗时、不在那台机器上装或改任何东西、不打印凭据。
5. **`raw/` 的保护规则**：根 `.gitignore` 有 `out/` 而**没有** `raw/`，权重派生的金标准数据因此**不受根规则保护**。
   已由 A 侧新增 `artifacts/golden-run/.gitignore`（`raw/` + `out/`）堵住；**任何权重派生数据一律不得入库**，
   审计要求：`git ls-files` 中不得出现 `.safetensors` 或 `golden-run/(raw|out)/**`。

## 残留未知（继续挂着）

1. 多窗口路径未验证（本决定第 4 条即为解它）；2. seed/RNG 语义未对齐；3. 模型卡 326 M vs 实测 191.3 M；
4. 训练数据 Bones Rigplay 1 的许可；5. 文本编码器链路（Llama-3 ＋ LLM2Vec）的许可——v1 只消费预计算 embedding 规避。
