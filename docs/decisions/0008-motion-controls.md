# 0008 · 参数真正生效 ＋ 路由按"动作类型"收紧（提案：判据先冻结）

**背景**：用户在页面上实测 chatbox ＋ 路由 ＋ 接续，三件都工作（`state=ok`、`route=compose`、
概率有分布、第 0 帧 = 上一段末帧 0.000 mm、保守分支话术正确）。但暴露两件事：

1. **参数只被"携带"，没有"生效"** ✗ —— `speed` / `amplitude` 出现在 `decision.params` 里、
   在 bubble 里被打印，但**没有任何一条路径把它送进采样器**；画面上永远是同一条走。
2. **`compose` 把"动作类型完全不同"当成"参数组合"** ✗ —— 「爬下前行」「向前跳」被判
   `compose`，于是系统答的是"用走的动作调速度"，而不是"换一种动作"。

本决定在动手**之前**冻结这两件事的判据。下面的表格是预注册的：实现完成后只允许**逐条对照**，
不允许放宽。

---

## 一、参数怎么影响采样（先把机制写死）

### 1.1 明确回答"后处理式形变"还是"条件输入"

**两者都用，且分界线是清楚的**：

| 参数 | 条件输入（改变送进采样器的东西） | 后处理式形变（改变出来的帧） |
|---|---|---|
| `speed` | **是**：`source_frames` 由 `speed` 决定（见 1.2） | **是**：时间轴线性重采样 |
| `amplitude` | 否 | **是**：逐帧逐关节旋转角缩放 |
| `expression` / `gaze` | **都不是** ✗ | **都不是** ✗（占位，见 §4） |

所以**不允许**把 `speed` 说成"纯后处理"，也**不允许**把 `amplitude` 说成"条件输入"。

### 1.2 `speed` —— 时间轴缩放（条件输入 ＋ 重采样）

作用对象：**整段片段的采样时间轴**，不是某一块特征。

设输出片段长度为 `T_out` 帧（由 `duration` 决定，**不变**），`s = speed`：

```
source_frames(T_out, s) = T_out                              , s <= 1
                        = ceil_to_horizon(T_out * s)         , s >  1
```

* `s <= 1`：源帧数不用变（读指针 `i*s` 永远落在 `[0, T_out)` 内）。
* `s > 1`：必须**多生成**源帧，否则读指针超出源长度，尾部只能冻结 —— 冻结会把速度统计
  拉回 1.0，判据 2 就不可能成立。这是"条件输入"那一半存在的原因。
* 上取整到 `horizon` 的整数倍，是因为 `validate_duration` 已经冻结了
  "片段长度 = 整个 horizon"这条规矩，控制层不去松动它。
* 上限 `CONTROL_MAX_SOURCE_FACTOR = 2.0`：`s > 2` 时**具名失败**
  `control_speed_out_of_range`，不静默截断。

重采样（对**每一个**特征块都做，保持帧内自洽）：

```
out[i] = lerp(src, i * s)          i = 0 .. T_out-1
```

* `foot_contacts`（4 个二值位）用**最近邻**，不做线性插值：插值会造出 0.5 这种
  不存在的接触状态。
* `root_pos` / `global_root_heading` / `local_joints_positions` / `global_rot_data` 线性插值。
* `global_root_heading` 是 `(cos θ, sin θ)`，线性插值后**重新归一化**，否则它不再是单位向量。
* `velocities` 是"米/秒"，本来就是时间归一化的量；同一段动作被压缩进同样的帧数里，
  输出的瞬时速度就是源速度的 `s` 倍，所以该块**乘 `s`**。不乘的话特征向量会自相矛盾
  （存储的速度和逐帧位置差分对不上）。

`s = 1` 是**恒等**：重采样在整数下标上必须短路成逐位复制，不允许经过浮点插值。

### 1.3 `amplitude` —— 关节旋转幅度（纯后处理）

作用对象：`global_rot_data` 块（`J*6`，`J = layout.nbjoints`），即**全局关节旋转**。

```
R_j   = cont6d_to_matrix(rot6d_j)          # 已有实现，model/skeleton.py，不改语义
(q,θ) = axis_angle(R_j)                     # 轴 + 角
R'_j  = axis_angle_to_matrix(q, amplitude * θ)
rot6d'_j = matrix_to_cont6d(R'_j)
```

* **只碰旋转，不碰平移**：`root_pos` / `local_joints_positions` 不被 `amplitude` 改动。
  这样"幅度判据"和"速度判据"在统计上互相不污染。
* 渲染确实会跟着变：`posed_joints_from_features` 是对 `global_rot_data` 做 FK
  （`model/skeleton.py:410-411`），所以旋转缩放＝四肢摆幅真的变大变小。
* `local_joints_positions` 会因此与旋转**不再严格一致**。这是已知取舍，写在 §4。

### 1.4 接续的边界帧必须豁免

0007 与既有判据要求：接续时**第 0 帧 = 上一段末帧**（实测 0.000 mm）。因此：

* `speed`：`out[0] = lerp(src, 0*s) = src[0]`，**天然**逐位相等 ✓。
* `amplitude`：会把第 0 帧的旋转也缩放，**破坏**这个等式 ✗。所以控制层有一个显式开关
  `preserve_first_frame`；接续路径传 `True`，第 0 帧的旋转**原样保留**。
  代价是第 1 帧起才生效，接缝处有一个单位的幅度不连续 —— 这是"接续不退化"换来的，
  写在 §4，不掩盖。

非接续（`reset` / 第一段）路径传 `False`，整段都生效。

## 二、预注册判据（先写死，之后不许放宽）

统计量定义（都在**物理单位**下算，不在归一化空间；实现于 `src/ardy_mlx/control/stats.py`）：

* `displacement_m`：`root_pos` 首末帧在 `x-z` 平面的距离（米）。**不用 `y`**：`y` 是
  竖直方向，跳跃会污染"前进位移"这一维。
* `mean_speed_mps`：逐帧 `‖Δ(x,z)‖` 的均值 × `fps`（米/秒）。
* `joint_rotation_deg`：对每帧（接续时从第 1 帧起）、每个关节，取旋转矩阵的
  axis-angle **角度**，再取均值（度）。

| # | 判据 | 阈值 | 可证伪方式（负对照） |
|---|---|---|---|
| 1 | 固定 `speed=amplitude=1.0` 时，控制层输出与输入**逐位相同** | `np.array_equal` 为真 | 让恒等路径也过一遍浮点插值 → 必须出现非零差异 |
| 2 | `speed=0.5` 与 `speed=1.5` 在**单位时间位移**上可分 | `mean_speed(1.5)/mean_speed(0.5) = 3.0 ± 20%`（且两档各自 ≠ 1.0） | 把 `speed` 参数丢弃（恒等）→ 比值必须是 1.0，判据必须红 |
| 3 | 同上，**总位移**可分 | `displacement(1.5)/displacement(0.5) = 3.0 ± 20%` | 同上 |
| 4 | `amplitude=0.5` 与 `amplitude=1.5` 在**关节旋转幅度**上可分 | `joint_rotation(1.5)/joint_rotation(0.5) = 3.0 ± 20%` | 把 `amplitude` 丢弃 → 比值必须是 1.0，判据必须红 |
| 5 | **不串扰**：`amplitude` 不改变 `displacement_m` | 逐位相同 | 顺手改 `root_pos` → 判据必须红 |
| 6 | 接续第 0 帧 = 上一段末帧 | 差 ≤ 0.001 mm（即 0.000 mm） | 不对第 0 帧豁免 `amplitude` → 必须红 |
| 7 | 越界是**具名失败**，不是钳位 | `speed=3.0` / `amplitude=0.0` / `nan` 各抛 `ControlError`，名字进 `error` 字段 | 悄悄 `clamp` → 测试必须红 |

容差 20% 的理由：`speed=0.5` 时 `T_out*s` 只有半个片段的源可读，端点效应（首末帧是
极值还是零速）会带来百分之几的偏差；插值本身在 `fps=20` 下也是分段线性的。20% 远小于
判据想区分的 3× 差距（1.0 vs 3.0），所以它挡得住"参数没接进去"，又不至于因为端点效应误报。

## 二·修订（0008-A）：上面第 2、3 条判据的**前提写错了**

**修订时间**：实现完成、第一次用**真实金标准片段**（`artifacts/golden-run-4s`，80 帧）测量之后，
在**任何验收结论被写下之前**。原始表格原样保留在上面，**不修改**，以便读者看到改了什么、为什么。

**错在哪**：第 2、3 条把"位移比 ≈ 速度比"当成了恒等式。它**只在源动作速度恒定时**成立。
真实的金标准走路片段有**起步加速段** —— 实测每帧速度（m/s，每 5 帧取样）：

```
[0.0145 0.0214 0.0204 0.0354 0.0510 0.2180 0.3352 0.1772 0.3792 0.1654 0.0980 ...]
```

前 20 帧几乎静止，约第 25 帧才到 0.42 m/s。于是 `speed=0.5` 的片段（40 帧输出只覆盖
源的前 20 帧）**整段都落在起步段里**，位移比自然远大于 3：

| 源 | `disp(1.5)/disp(0.5)` | `speed(1.5)/speed(0.5)` |
|---|---|---|
| 恒定速度合成源（1.0 m/s） | **3.0000** | **3.0000** |
| 真实金标准走路（有起步段） | 13.82 | 15.60 |

所以第 2、3 条**按原样在真实片段上是不成立的**，不是实现错了。

**修订后的判据（现在冻结这一版）**：

| # | 判据 | 阈值 |
|---|---|---|
| 2a | **恒定速度源**上，同长度输出的位移比与速度比 | 都 = `3.0 ± 1%`（恒等式，应收得紧） |
| 2b | **真实金标准片段**上，`speed ∈ {0.5, 1.0, 1.5}` 的位移与平均速度**单调**且 `1.5/0.5 > 3` | 单调 + 比值 > 3；**报告实测值**，并注明它含起步段效应 |
| 2c | **负对照**：`speed=1.0`（恒等）时比值 = 1.0000 | 逐位恒等路径，比值必须**恰好** 1 |

第 4 条（`amplitude` 旋转幅度比 = 3.0 ± 20%）**不需要修订**：旋转角缩放是逐帧逐关节的
线性变换，与动作的时间剖面无关。实测 19.1642° → 57.4926°，比值 **3.0000**，饱和比例 0.0。
第 5 条也实测通过：`amplitude` 两档下 `displacement_m` 与 `mean_speed_mps` **完全相同**
（0.136988 / 0.118887），零串扰。

## 三、路由按"动作类型"收紧

### 3.1 新的窄判断 `motion_type_known`（Noul）

语义：**库里已有的动作类型，是否覆盖这句话要求的类型**。instruction 里必须写清那组对比：

* **同一动作换节奏/幅度** → "walk" 是已知类型，"慢慢走过去" 只是把 walk 放慢 → 真。
* **换一种动作** → 库里没有该类型（例如侧手翻、倒立行走）→ 假。

### 3.2 路由定义收紧

| `motion_type_known` | 允许的 route | 不允许 |
|---|---|---|
| 真 | `library` / `compose` | — |
| **假** | **`generate`** | `library` / `compose` ✗ |

`compose` 的语义同时收紧为"**同一个动作**换节奏/方向/幅度"，**不再**包含"把两个已有动作
拼起来" —— 后者现在属于"换一种动作"，除非库里真有一条就是那个动作。

判定发生在 **`decide()` 里（纯函数、代码）**，不是靠模型自觉：模型给 `compose` 而
`motion_type_known` 为假时，`decide` 把它改判成 `generate`，并在 `reason` 里写明
`motion_type_known=… < … -> generate`。这与本文件既有设计一致：**模型只回答封闭问题，
把答案变成动作的地方只有一处**。

假分支**不得**退化成"用走的动作调速度"✗ —— 这正是用户报的那个 bug。

### 3.3 `state` 里必须传动作类型摘要

`context.library_types`：**去重后的短类型标签列表**，不是整库长文本。

* 每个 entry 的文本先过一个**动作类型词表**（正则，最长匹配），命中就取类型标签
  （`walk` / `run` / `jump` / `hop` / `crawl` / `climb` / `wave` / `sit` / `turn` / …）。
* 没命中的（例如用户自己敲进去的中文残句）取**截断标签**：`text[:24]` ＋ `…`。
* 去重后按字典序，**上限 `LIBRARY_TYPE_LIMIT = 24` 条**；超出部分不丢信息，
  记成 `"…(N more)"` 一个条目说明被截了多少。

`context.library_entries` **保持原样**（`library_pick` 需要它按条选），
新增的是 `library_types` 这个"类型视角"。两者一起进 `state`。

## 四、诚实边界（不许在页面或文档里含糊）

* `expression` / `gaze`：**未生效** ✗。骨架没有脸、没有眼睛，两个字段继续标
  `expression_placeholder: true`，并且 `applied` 列表里**不出现**它们。
* `amplitude` 改了 `global_rot_data`，不改 `local_joints_positions`：
  两者会不一致。渲染走 FK（用旋转），所以画面是对的；特征向量里的
  `local_joints_positions` 是"原样保留"的。**已知取舍**。
* 接续时 `amplitude` 从第 1 帧起生效（§1.4），接缝处幅度不连续。
* `s > 1` 需要多生成源帧：**金标准噪声录不到那么多窗口**。沿用既有
  `CONTINUATION_NOISE_FALLBACK` 的先例，改成随机噪声并**具名**记进 `noise` sidecar
  （`fallback_reason = control needs N windows, recording holds M`），不静默复用同一份 `x_T`。
* 速度与幅度都是**形变**，不是模型重新学的动作：`speed` 会带来脚滑，`amplitude`
  会让姿态在极端值下不自洽。页面上要写明这是取舍，不是 bug。
