Read this before comparing clips. A prompt with a cached reference bf16 vector is conditioned on that vector, and only those clips are comparable with the Reference (golden) overlay. Any other prompt is encoded on this machine by the local MLX text encoder — close to the reference, but a different artifact, so its motion is a different, equally valid sample and is not aligned with the golden clip. Encoding happens once per prompt and is then cached under artifacts/embeddings/<encoder-id>/<prompt-hash>.npy. If the encoder is missing or refuses, the request fails by name (local_encoder_unavailable / local_encoder_failed) — the server never substitutes another prompt's vector. Post-processing is not built, so the clip carries foot skating, and the MLX RNG is not CUDA's Philox stream. See docs/VIEWER.md.

Continuity. A new prompt does not reset the character. The next clip is generated from the clip on screen: its trailing frames are the window's clean history, and the accumulated root translation and the heading are carried over, so frame 0 of the new clip is the frame you were already looking at. Position and velocity are continuous across that seam; acceleration is not (the 4-frame conditioning window has no acceleration channel). The reference's own x_T only reproduces the reference from its own beginning, so a continuation always uses the local random noise and says so. A forced reset is available over the API ("reset": true) and is the negative control the continuity numbers are measured against.

No loop. Playback is a continuous stream: while a clip plays, the next one is generated ahead of it and appended to the run, so the character never returns to the start of a clip. The trajectory, the camera and the frame counter all continue across a segment seam — the counter is the global frame in the whole run and only ever goes up. A sentence typed while a clip is playing is not applied mid-clip: it is stored and takes effect at the next segment boundary (the HUD's next条件 row says which conditions that will be). If generation cannot keep up, playback holds the last frame and the stream row says the buffer ran out — it never loops to cover the gap. The Loop checkbox above is the explicit, default-off exception, for studying a single clip; when it is on, the position display goes backwards, which is why it is labelled.
